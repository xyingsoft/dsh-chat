## 31. 标识、租户与会话隔离

`OrganizationId`、`WorkspaceId`、`ProjectId`、`GroupId`、`ResourceId`、`CollaborationSessionId`、`BotId`、`AccountId` 和 `DeviceId` 都是**服务端生成的品牌化不透明 ID，不能由显示名、仓库 URL 或客户端随机字符串替代**。

> **所有数据库主键、唯一索引、队列分区键、对象存储路径、缓存键、审计事件和异步任务都以前缀 `OrganizationId` 隔离。** 跨组织查询在 SQL 层、ORM/查询构造层和授权层**都**必须显式带组织条件。

会话分为四类：浏览器到 host 的本地会话、host 到 relay 的设备会话、组织资源访问会话、以及协作/Bot DSH 会话。

浏览器会话只在 loopback 或受认证的 DSH Web 连接中有效，使用 `HttpOnly`、`Secure`、`SameSite=Strict` cookie 与 CSRF token；**它不能直接携带 relay access token**。

设备会话绑定 `AccountId + DeviceId + keyFingerprint + tokenId`，有短访问期、可轮换刷新期和 token 撤销列表。刷新、设备添加、密码重置、导出、组织切换和高风险动作都要求重新签名证明。

组织资源访问会话额外绑定 `OrganizationId`、成员状态、角色/ACL 修订号和风险状态。资源缓存命中前比较该修订号；成员被移除、权限收回、组织挂起或设备受控时，旧会话立即无效。

协作会话和 Bot 会话使用独立 DSH `SessionId`、独立存储目录、独立工具许可、独立预算和独立密钥引用。**它们不能读取个人 DSH 会话，也不能通过共享内存、缓存键或日志访问另一个组织的上下文。**

## 32. 授权链、强制确认与黑名单

服务端授权按**固定顺序**执行：验证 TLS/relay 指纹，验证设备签名和 token，检查 token/设备/IP/账号黑名单，检查风险状态和套餐限制，解析 `OrganizationId`，检查成员状态，计算角色与资源 ACL，检查资源版本/有效期，最后执行领域状态机。

任何一层拒绝都返回最小错误信息；**对于调用者无权知道是否存在的对象，统一返回 `NOT_FOUND_OR_FORBIDDEN`**。

强制确认使用一次性 `ConfirmationChallenge`，绑定操作者、设备、组织、动作、资源摘要、策略版本、过期时间和幂等键。高风险动作包括新增/恢复设备、改变密码或认证方式、导出组织资源、共享私人会话、开启写仓库自动化、发布高权限插件、启用公共 Bot、删除组织、修改预算或关闭安全策略。

> **挑战只有经设备签名和用户界面明确确认后才能消费；页面刷新、重复请求或网络重试不能绕过确认。** 过期挑战返回 `CONFIRMATION_EXPIRED`，必须重新展示摘要。

黑名单分为 token、设备指纹、账号、IP/CIDR、自治系统网络、仓库来源、插件摘要和恶意附件摘要。每条记录有来源、范围、原因、创建者、过期时间、申诉状态和审计事件。

命中账号、设备或 token 黑名单时立即撤销会话；命中网络或来源黑名单时按策略拒绝请求、提高风险等级或要求二次验证。普通用户不能通过错误信息枚举黑名单内容。

## 33. 连接、外部网络与 SSRF 防护

### 33.1 短连接与长连接

创建、读取、上传预约、ACL 判定和幂等查询使用短 HTTPS 请求，带严格的请求大小、超时、并发和响应大小上限。

消息拉取、通知和在线状态使用 host 到 relay 的长轮询或 HTTP/2 流；浏览器只连接 host 的同源事件流。浏览器断开不会中断 host 的消息投递循环。

每条长连接都有 `ConnectionId`、设备会话、组织范围、最后活动时间、最大存活期、心跳截止时间和取消信号。状态为 `opening`、`active`、`draining`、`closed`、`expired` 或 `rejected`。

连接超过最大存活期、权限修订变化、设备撤销、风险管制、组织挂起或服务器平滑重启时进入 `draining`，停止接受新订阅，发送可恢复原因并关闭；客户端用同一设备会话重新认证和补拉，不依赖连接内存保存业务事实。

长连接只传递事件提示和有限批次，不能代替持久收件箱、消息队列或资源下载。连接背压超过阈值时丢弃可重建的提示帧、保留游标并要求客户端补拉；不得丢弃已接收消息或授权变更。

### 33.2 受控出站

仓库验证、webhook 注册、插件源拉取、恶意文件扫描回调和 Bot 的外部工具调用**全部经由 `EgressService`，业务代码不得直接使用通用 HTTP 客户端**。每次出站请求都记录发起服务、组织、用途、目标来源策略、认证材料引用、解析结果和审计 ID；**请求体、响应正文、token 与 webhook secret 不写入普通日志**。

`EgressService` 只允许组织策略列出的协议、端口、主机名和已批准 Git 提供方。它在连接前解析 DNS，**拒绝 loopback、私有地址、链路本地地址、组播、保留地址、IPv6 本地地址、Unix socket 和非 HTTP(S) scheme**；**实际建连时再校验目标 IP，阻止 DNS rebinding**。所有重定向逐跳重新执行上述校验，**禁止由 URL 中的用户名、代理环境变量或自动凭证转发改变目标**。

L3 的出口代理是 `EgressService` 的**唯一网络出口**，而不是仅靠 `HTTP_PROXY` 环境变量。**运行身份没有直连外网权限**；代理按服务身份和 allowlist 建立受限连接、设置连接/响应大小/重定向上限并验证 TLS。**自建 Git 服务只能由管理员登记为受控私网端点**，并在独立网络策略、专用连接器和审计下访问，不能通过普通仓库 URL 绕过私网封锁。

## 34. 风险管制与账号接管防御

relay 为每个设备保存近期 IP 前缀、自治系统网络、粗粒度国家/区域、首次/最后出现时间和风险评分；不把精确地理位置用于产品展示或绩效分析。

新国家/区域、新自治系统网络、短时间不可能移动、代理/匿名网络、指纹变化、重复签名失败或异常流量会创建 `SecurityRiskEvent`，状态为 `observed`、`pending_confirmation`、`restricted`、`resolved`、`suspended` 或 `false_positive`。

达到组织策略阈值时，设备**立即进入 `restricted`**：relay 撤销该设备的组织访问 token，关闭其长连接，阻止项目、群、公共插件、共享资源、仓库、Bot 和分析数据的读取或写入。**host 收到该状态后清除该组织的解密材料和敏感缓存，只展示安全处理页**。

relay 向设备所有者和组织管理员写入高优先级通知，并向账号已验证邮箱发送异地登录安全邮件。邮件包含设备名称、指纹后缀、粗粒度地区/网络、时间、风险原因和一次性安全处理链接，不包含 access token、设备私钥、完整 IP 或组织资源信息。

安全处理链接状态为 `issued`、`opened`、`authenticated`、`consumed` 或 `expired`，绑定账号、风险事件、邮件验证状态、过期时间和一次性随机值哈希。**邮件扫描器或打开链接本身只会使其变为 `opened`，不会自动批准或撤销设备。**

用户打开链接后进入 relay 的安全中心，必须用密码、已授权设备签名、企业单点登录或配置的第二验证因素完成认证。认证成功后展示明确的“停止此异地设备”快捷按钮和风险摘要。

点击该按钮会在一个事务中将目标设备改为 `revoked`、撤销其 token、关闭其长连接、取消其未提交写租约、发布缓存失效和审计事件；随后向用户和组织管理员发送“设备已停止”通知。该动作不撤销当前已认证的处理设备。

用户也可以标记可信网络、批准一次性恢复或请求管理员处理；管理员可暂停设备，但不能代替用户绕过必须的身份确认。

在风险处理完成前，该设备不能看到任何组织项目和公共内容。超过处理期限或持续异常时，设备进入 `suspended`，只能进行恢复、导出个人安全记录和联系管理员的最小操作。

地理位置误差、旅行和企业 VPN 是预期情况，因此策略使用可配置风险评分和申诉路径；**“新地区”本身不是身份认证，也不能绕过设备签名和组织权限**。

## 35. 加密与密钥

P0 到 P3 **强制 TLS 1.3 或更高版本**、HSTS、受限密码套件、证书透明度检查和组织 relay 指纹固定。**证书轮换必须由旧证书密钥或组织离线根签名，并经过管理员确认；意外变化按中间人风险处理。**

服务器侧加密使用信封加密：对象、附件、备份和敏感数据库列由数据密钥加密，**数据密钥由 KMS/HSM 中的组织密钥加密**。应用进程只按最小权限取得短期解密许可，密钥访问记录审计。

P4 的私聊端到端加密使用经独立安全审计的双棘轮实现和设备预密钥包；relay 只保存设备公钥包、密文信封、必要投递元数据和不可逆的去重标识。

群端到端加密使用经审计的成员密钥管理协议。成员加入、移除、设备撤销和密钥恢复都会生成**新的 epoch**；**新成员不能解密旧 epoch，已移除成员不能解密新 epoch**。客户端在密钥指纹变化时**必须**显示安全确认，未确认时停止解密和发送。

> **端到端加密不等于服务器侧加密。** 启用后，服务器仍能执行成员授权、配额、队列、流量防护和密文保留，但无法生成基于消息正文的服务端搜索、明文审核或 AI 总结；**这些功能必须由用户在设备侧明确选择**。

### 35.1 加密模式功能矩阵

`OrganizationEncryptionPolicy` 明确定义功能矩阵，不能只用一个开关隐藏实现差异：

| 模式 | 消息正文 | 群公共 Bot | 服务端搜索/正文分析 | 可用指标 |
|---|---|---|---|---|
| `server_managed` | relay 可按权限读取 | 可用 | 可用 | 消息元数据、项目流转和策略允许的正文派生指标 |
| `e2ee_without_bot` | 仅成员设备解密 | 强制禁用 | 强制禁用 | 客户端签名的最小用量/工作项/提交元数据 |
| `e2ee_with_bot_member` | 成员设备和显式 Bot 设备解密 | 仅作为可见群成员可用 | relay 强制禁用 | 同上；Bot 只处理被策略授权给其设备的内容 |

切换到端到端模式前，relay 计算受影响群、Bot、插件、搜索索引和报表能力，向管理员展示降级清单并要求**强制确认**。**切换后，不能工作的入口从 UI、API 目录和自动任务中移除，而不是允许安装后持续报错。**

`e2ee_with_bot_member` 中 Bot 拥有独立设备指纹和可见身份，成员在加入或切换时明确确认该 Bot 能解密哪些群 epoch。移除 Bot 会触发群 epoch 轮换；Bot 不能读取轮换后的消息，除非管理员再次显式添加。

服务器私钥、组织 KMS 密钥和设备私钥**彼此独立**。**任何组件不得复用一个“共享秘密”作为 TLS、设备认证、数据加密和消息加密密钥。**

> 加密模式对搜索能力的降级矩阵，见[协作能力需求 §21 搜索与索引](../01-requirements/02-collaboration-requirements.md#21-搜索与索引)。

## 36. 缓存、保留与恢复

缓存只保存可重建数据，并以 `OrganizationId + policyRevision + resourceVersion` 命名空间隔离。授权结果、群花名册、插件目录、资源元数据和分析聚合可短暂缓存；消息正文、设备私钥、明文附件、密码验证材料和解密后的 E2E 内容不能进入共享缓存。

权限、成员、风险、黑名单、密钥 epoch、资源版本和组织状态变化会发布失效事件。失效事件优先于普通通知处理；缓存无法确认最新修订时必须拒绝访问或回源验证，不能继续返回过期授权数据。

### 36.1 保留策略基线

所有组织在创建时都获得明确的 `RetentionPolicy`，不能以 TBD 状态进入 P0。自建组织可调整，但默认值和最小安全值如下：

| 数据 | 自建组织默认 | 团队版默认 | 企业版 | 说明 |
|---|---:|---:|---|---|
| 已送达消息与群日志 | 90 天 | 180 天 | 合同/策略配置 | 到期前发送容量与保留提醒 |
| 未 ACK 私聊队列 | 14 天 | 30 天 | 30 至 90 天 | 到期后写发送方可见终态失败 |
| 消息附件授权 | 30 天 | 90 天 | 策略配置 | 仍被资源版本引用的 blob 不删除 |
| 资源软删除恢复窗口 | 30 天 | 60 天 | 策略配置 | 之后进入物理清理 |
| Bot/协作执行日志 | 30 天 | 90 天 | 策略配置 | 不含被禁止保留的秘密 |
| 审计与风险事件 | 365 天 | 365 天 | 合同/法规配置 | 法律保留可延长 |

`RetentionPolicy` 同时定义每类对象的字节配额、预警阈值和清理批次大小。容量达到 80% 时通知组织管理员，达到 90% 时限制新的大对象上传，达到 100% 时拒绝会增加存储的写入但不删除已有已接收数据。

清理任务分为过期租约回收、未 ACK 队列保留期处理、上传预约回收、临时对象删除、消息/附件授权到期、资源软删除转物理删除、缓存淘汰、审计归档、备份过期和分片压缩。每个任务记录扫描游标、候选对象、策略版本、执行结果和可重试错误。

**删除遵循“先不可见、后保留、再物理清理”的流程。** 受法律保留、审计冻结或未完成恢复的对象不会物理清理；**清理失败进入 `dead_letter` 并告警，而不是静默跳过**。

relay 和 host 均使用受限大小的 LRU 缓存、对象流式传输和分块校验，避免把大文件或大群历史整体装入内存。附件下载和上传支持断点续传，但每个分块都绑定预约、摘要、组织和权限。

备份采用跨可用区/介质的加密快照与持续日志，定期恢复演练到隔离环境。**恢复完成前服务处于 `read_only_recovery`，禁止写入，避免新写入和旧数据分叉。**

## 37. 审计事件模型

审计是 P0 即装载的核心能力，因此 `AuditEvent` 的结构属于 `@dsh-chat/contract`，不由各插件自行定义。

每条审计事件包含不可变 `AuditEventId`、`OrganizationId`、事件类型、发生时间、服务端序列号、操作者身份（`AccountId` 或服务账号）、`DeviceId`、来源 IP 前缀与粗粒度区域、目标对象引用、操作结果、错误码、策略版本、关联操作 ID/幂等键、关联领域事件 ID 和调用链 ID。

**审计事件记录事实与引用，不记录内容。** 消息正文、附件字节、提示词、模型输出、密码、token、密钥、webhook secret 和恢复材料**一律不进入审计记录**；需要表达对象身份时使用不可逆摘要或资源版本引用。

事件类型至少覆盖：身份与设备（注册、认证、恢复、撤销、风险状态变更）、组织与授权（成员、角色、ACL、策略、套餐、确认挑战）、内容（上传、扫描、下载授权、隔离、删除、保留清理）、协作（共享、协作会话、执行租约、产物发布）、仓库与出站（绑定、验签、提交验证、受控出站）、插件与 Bot（提交、审核、发布、启用、撤销、调用）、分析与计费（策略变更、明细查看、导出）、以及运维（迁移、恢复、水位对账、密钥轮换、黑名单）。

**审计写入与领域写入处于同一事务**：领域对象、outbox 与审计事件一并提交，因此不存在“操作成功但无审计”或“有审计但操作未生效”的状态。**审计写入失败即整个命令失败。**

**被拒绝的操作同样产生审计事件**，记录拒绝所处的授权层与错误码。这使得越权尝试可被检测，但返回给调用者的错误信息仍遵循最小披露原则。

审计存储的不可变性按部署层递进，**功能矩阵必须显式声明而不是笼统承诺“不可篡改”**：

| 层级 | 不可变形态 | 说明 |
|---|---|---|
| L1 | 仅追加表 + 应用层禁止更新/删除 | **具备数据库权限者仍可改写；文档不得宣称防内部人篡改** |
| L2 | 仅追加 + 每日哈希链锚点 + 独立备份 | 可检测事后批量篡改，锚点与主库分离存储 |
| L3 | 逐条哈希链 + 外部不可篡改归档 + 独立密钥签名 | 支持第三方验证与法规导出 |

L2 起每条审计事件包含前一事件摘要，形成按 `OrganizationId` 分区的哈希链；链断裂检测到时产生高优先级运维告警并进入调查状态，不自动修复。

审计查询是受限能力。审计者角色默认只读取被授权范围的审计记录与元数据，不读消息正文；查看个人分析明细、导出审计和跨项目查询本身也是被审计的动作。审计记录按 `RetentionPolicy` 保留 365 天或按合同/法规配置，法律保留可延长；审计数据不参与排行、报告与模型上下文。

## 38. 账号注销、导出与合规

账号、组织成员关系和组织数据是三个不同的所有权层次，因此退出组织、组织删除和账号注销是三条独立流程，不能互相代替。

### 38.1 数据导出

数据导出是成员的常规能力，不是注销的附属步骤。导出请求状态为 `requested`、`preparing`、`ready`、`downloaded`、`expired` 或 `failed`；导出包加密、绑定请求者、限定下载次数与有效期，生成与下载都写入审计。

导出范围按主体区分：

| 主体 | 可导出内容 | 明确不含 |
|---|---|---|
| 成员个人 | 自己发送的消息、自己上传的资源版本、自己的工作项、个人用量明细、账号与设备安全记录 | 他人私聊、未授权资源、他人用量、组织审计全量 |
| 组织管理员 | 组织结构、成员关系、策略、资源目录元数据、已授权范围内的群日志与资源 | 成员私聊、成员私人 DSH 会话、E2EE 密文正文 |
| 审计者 | 被授权范围的审计事件与元数据 | 消息正文、秘密、密钥材料 |

管理员导出是高风险动作，需要 `ConfirmationChallenge`，并向被涉及成员写入通知；组织可配置双人审批。**导出不得成为绕过资源 ACL 的旁路，导出内容按请求者当时的权限逐条裁剪。**

### 38.2 账号注销

账号注销由账号所有者发起，状态为 `requested`、`pending_transfer`、`grace_period`、`anonymized` 或 `purged`。发起注销需要重新认证与确认挑战。

注销前**必须先解决所有权阻塞**：账号是任一组织的唯一所有者时进入 `pending_transfer`，**必须先完成组织所有者转让或组织删除**；存在未结算账单、法律保留或未完成恢复流程时同样阻塞。**系统不因个人注销而使组织失去管理主体。**

注销进入默认 30 天的 `grace_period`，期间账号不可登录但可由本人撤销注销。**宽限期结束后执行匿名化而非物理删除全部记录**：

- 账号档案、邮箱、账号名、设备公钥、IP 与区域历史、第二因素与恢复材料物理删除。
- 消息与群日志正文按其所属组织的 `RetentionPolicy` 处理，作者字段替换为**不可逆的 `AccountTombstone`**，保留稳定的匿名标识以维持会话可读性与序列完整性；**不追溯删除他人已合法接收的协作事实**。
- 联系人关系与拉黑记录删除；对方界面显示为已注销账号。
- 群成员身份转为历史事件，`membershipRevision` 不回滚。
- 工作项、资源版本与已验证提交的归属转为 `AccountTombstone`，保留项目交付事实与审计完整性。
- 分析明细中的个人维度删除或聚合到匿名分组，个人排行历史移除。
- 审计与风险事件保留至各自保留期，操作者字段替换为 tombstone；受法律保留的记录延长保留。

**匿名化不可逆。** 文档必须明确：**注销不删除他人副本、已导出内容、已下载附件，也不撤销已发生的协作事实**；这与撤回和共享撤销的边界声明一致。

### 38.3 组织删除与数据导入

组织删除同样使用宽限期。发起删除需要组织所有者确认挑战与双人确认（企业版可配置），随后进入默认 30 天 `grace_period`：组织转为只读，停止新写入、Bot 调用、插件启用和外部通知，保留导出与恢复能力，并向全体成员与账单联系人发送通知。宽限期内可由所有者撤销。宽限期结束后按对象类型执行物理清理，审计与合规记录按法规保留期单独留存；清理进度可查询，失败进入 `dead_letter` 并告警。

自建组织的部署管理员可以直接删除底层数据库与对象存储，这超出应用层承诺范围；文档不得暗示应用层删除流程能约束具备基础设施权限的运维者。

数据导入与跨平台迁移**不在 P0 至 P3 范围内**。企业迁移需求列入开放决策，需先确定导入范围、作者映射、去重规则、权限重建、历史授权推导和导入内容的审计标记方式；**在此之前导入入口显示为未安装**。

## 39. 安全规范清单

以下条目是对前述各节的强制性汇总，用于评审逐条核对。

- relay 通信使用 HTTPS；**HTTP 只允许在明确的 loopback 开发模式下使用**。
- host 固定组织 relay 的 TLS 证书/公钥指纹；**未被旧密钥或组织离线根签名确认的轮换一律视为中间人风险，不允许降级连接**。
- 浏览器写路由要求同源校验和每个会话的 CSRF token；**开发模式外，缺失或 `null` 的 Origin 一律拒绝**。
- **token、refresh credential、私钥、原始媒体路径、relay 注册邀请码不得出现在浏览器状态、URL、日志、遥测或错误信息中**。
- 密码只在 TLS 认证流程中使用，relay 只保存 Argon2id 验证值；密码重置、设备撤销和组织切换均需重新认证或已授权设备确认。
- 在线状态只暴露 host 存活提示，遵守成员选择的可见范围；它不记录键盘活动、页面内容或精确在线时长。
- 新地区、异常网络、指纹变化和异常流量按组织风险策略将设备置于受控状态；在重新验证或管理员处理完成前，该设备不能读取或写入任何组织项目和公共内容。
- 异地登录安全邮件使用短期单次链接；链接打开后必须重新认证，才可执行“停止此设备”，避免邮件扫描器、转发或被盗邮箱直接触发撤销。
- 所有外部请求和 relay 响应在使用前都要执行 schema 校验和请求体上限校验。
- 每次写操作都使用幂等键，并产生包含操作者、操作、目标、结果和关联 ID 的审计记录；审计记录不得包含消息正文或秘密。审计与领域对象在同一事务提交，审计写入失败即整个命令失败；被拒绝的操作同样产生审计事件。
- 高风险路径要求第二验证因素：新设备注册、账号恢复、认证方式变更、安全中心处置、组织所有权转让、组织删除和管理员导出。备用码只展示一次且只保存哈希；第二因素与 `RecoveryKit` 是独立路径，不能互相替代。
- 每次读取、下载、继续协作会话和 Bot 调用都**同时**校验组织成员状态、项目权限、资源 ACL、对象状态和有效期；**不能只根据前端是否显示入口授权**。
- **搜索索引不构成读取授权。** 每条候选结果在返回前逐条复检资源 ACL、历史授权区间、对象状态和有效期；复检失败的条目静默丢弃且不计入总数，避免以结果计数推断不可见内容。撤回、隔离、授权撤销和保留期到期必须使索引条目转为 `suppressed` 或 `purged`。
- 端到端加密模式下 relay 强制禁用正文索引；设备侧本地索引与解密材料同等保护，设备进入 `restricted` 时一并清除，界面必须显示已索引区间而不暗示结果为全量。
- 转发逐条复检原消息读取权与附件授权，复用同一 `BlobObject` 而不复制字节，且一律禁止跨组织转发；线程权限完全继承所属群与历史授权，不新建权限域。
- 评审批准只对锁定的产物版本生效，关联产物变化后自动 `superseded`；执行成功不等于产物被接受，候选产物必须经有写权限成员确认并通过版本比较才能成为当前版本。
- 评论中的 @ 提及只能指向对该对象已有读取权限的成员，提及无权限成员返回 `FORBIDDEN`，不因提及授予任何访问权；`comment` 访问级别不含改状态、发起或批准评审、再共享。
- 数据导出按请求者当时的权限逐条裁剪，不得成为绕过资源 ACL 的旁路；导出包加密、绑定请求者、限定下载次数与有效期，生成与下载都写入审计。
- 账号注销执行匿名化而非追溯删除他人已合法接收的协作事实；唯一所有者必须先完成所有权转让或组织删除，组织不允许处于无 `active` 所有者的状态。
- 通知摘要只展示接收人原本有权读取的最小信息；被撤销权限后，收件箱保留事件类型和时间，但不再展示敏感标题、内容或下载入口。
- 上传资源在 `available` 前必须完成摘要验证和组织策略要求的安全扫描；隔离、拒绝和删除操作都产生审计事件。
- 公共插件必须固定精确版本并通过组织允许的来源、签名和依赖策略；插件读取秘密、访问外网、调用模型或写项目资源前都要有显式能力授权。
- 仓库访问 token、webhook secret 和部署密钥只存入 relay 的受保护秘密存储；浏览器和普通群成员只能获得跳转链接与已授权的提交元数据。
- 代码提交归因必须经过远端仓库验证；客户端上报的 hash、AI 使用标签和变更统计都不能单独进入排行榜或月报。
- **Bot、AI、插件、仓库和外部工具输出一律按不可信内容处理**；只有客户端显式提交的交互意图能进入命令或工具执行路径。
- 分析事件只采集计算指标必需的最小元数据；**私人聊天、原始提示词、文件正文和私人会话不进入组织排行榜或报告训练上下文**。
- 个人分析明细、数据更正和排行可见性受组织保留期与访问策略保护，管理员的查看和导出行为必须审计。
- 输入限流按已认证账号、设备、目标，以及 relay 能够可靠识别的 IP 执行。
- relay 健康检查端点要求运维认证，或只输出不敏感的聚合就绪信息。
- 部署管理台与 CLI 走同一套认证、确认挑战与审计路径，**不设置绕过授权链的后门接口**。
- **日志与指标不得包含消息正文、附件字节、提示词、模型输出、token、密钥、webhook secret、完整 IP 或恢复材料**；查询词按组织策略脱敏且不写入普通日志。
- 向 Bot 传输上下文时必须让调用者可见，并遵循该 Bot 选择的保留策略。
- **P4 端到端加密使用经过独立安全审计的密码学库和协议；禁止自行实现棘轮、群密钥协商、证书校验或随机数算法。**

> 上述清单对应的安全回归用例库，见[测试与验收策略](../04-roadmap/04-test-strategy.md)。
