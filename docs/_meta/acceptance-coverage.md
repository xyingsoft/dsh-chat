# `P0-a` 失败路径覆盖

> **本文件由 `packages/chat/kernel/src/acceptance.host.spec.ts` 自动生成，请勿手工编辑。**
>
> 清单来自[迭代计划 §44.1.2](../04-roadmap/03-iteration-plan.md#4412-验收要求)。

| §44.1.2 的失败路径 | 验证方式 |
|---|---|
| 成员被移除后的访问拒绝 | 成员关系离开 active 后授权判定输入随之改变 |
| 审计写入失败导致整个命令失败 | 审计撞主键时同事务的消息写入一并回滚 |
| ACK 前 host 崩溃 | 拉取后不 ACK 并重开数据库，租约到期后消息重新可拉 |
| relay 重启 | 真实磁盘文件关闭重开，队列内容不丢失 |
| 重复投递 | 同一 (senderId, messageId) 重发返回首次的 DeliverySeq，队列不增 |
| 未授权发送被拒绝 | 非联系人时准入判定不放行 |
| 队列已满 | 容量检查在写入前，已接收消息不被淘汰 |
| 组织切换缓存隔离 | 切换后前一组织的桶被整个丢弃，不只是读不到 |
| 角色越权 | 开发者缺少 project.create，授权判定不放行 |
| 工作项依赖成环被拒 | 第二条边形成环时返回 DEPENDENCY_CYCLE 与环路径 |
| 评审批准后关联产物变化自动转 superseded | 批准锁定 v3，产物到 v4 后 canTransitionToDone 拒绝 |
| 限流在各维度按最严格者生效 | 设备维度满时账号维度尚有 8 次额度，仍然拒绝 |
| 被拒绝操作同样产生审计事件 | rejected 结局与错误码一并留痕 |

## 不在本表内的两类

- **跨源浏览器写请求** —— 需要真实 HTTP，验证在 `command-router.host.spec.ts` 与
  各端点测试中；本文件是库级验收，起不了 HTTP 服务。
- **插件卸载后不残留** —— 验证在 `index.host.spec.ts` 与 `index.client.spec.ts`，
  需要真实的 Cordis fiber 生命周期。

凭证重放、在线状态过期）不在 `P0-a` 范围。其中**凭证重放**已随设备签名一并实现，
