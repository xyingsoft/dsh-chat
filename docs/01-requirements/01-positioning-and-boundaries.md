本篇回答三个问题：这个产品是什么、给谁用、明确不做什么。后续所有技术决策都以本篇的边界声明为准绳。

## 1. 产品定位

`dsh-chat` 是 **DSH Web 中面向自建团队、受管团队和企业组织的协作平台**。

聊天是协作入口之一；组织成员还能在工作区和项目内分派工作、共享文件与 AI 产物、交接开发会话、使用经过审核的公共插件和 Bot，并查看与其权限相符的协作数据。

**它不是微信集成、微信替代品、微信协议实现或微信账号桥接。**

> **核心价值**：让人、项目资源和 DSH AI 工作流处于同一受控组织中。**聊天记录和私人 AI 会话严格分开**；用户只能主动选择内容提交给 AI，组织共享内容也**必须**经过明确授权。

## 2. 目标用户

产品面向三类用户：自行部署基础设施的个人/班级/私有团队，购买受管服务的团队，以及需要目录同步、审计和治理能力的企业组织。

每位成员在自己的 DSH Web profile 中运行 dsh-chat 插件；组织服务端决定身份、成员关系、套餐、资源权限、公共工具和组织级数据。

> 三类用户对应的运维责任、容量上限与可启用能力差异，见 [身份、组织与权限 §12 组织类型、容量与订阅](../03-details/01-identity-and-permission.md#12-组织类型容量与订阅)。

## 3. 能力边界与不做清单

**P0 到 P3 的 relay 仍可能读取明文消息**：传输中使用 TLS、在服务器侧加密存储投递和协作数据，但服务器持有解密能力。P4 的端到端加密使用独立审计过的密钥生命周期，使 relay 只路由密文和最少元数据。

早期版本**不提供**账号发现、移动推送、音视频通话，或可不经授权读取和发送聊天内容的 AI。

**DSH 智能体会话日志不是聊天历史。**

> **AI 摄入红线**：只有用户明确选择并触发 AI 操作的内容才能进入 AI 请求；这些内容在对模型可见前**必须**通过正常的 DSH 会话机制记录。

### 3.1 八条边界声明

以下边界在全文反复出现，集中声明以避免实现期误解。**这八条是评审时最容易被实现者误解的地方**：

| 边界 | 含义 |
|---|---|
| **撤回 ≠ 抹除** | 不承诺擦除已截图、导出、复制、设备缓存或经历史授权下载的内容 |
| **撤销共享 ≠ 删除** | 只阻止后续读取，不删除已下载的本地副本 |
| **注销 ≠ 抹除他人副本** | 匿名化保留他人已合法接收的协作事实 |
| **执行成功 ≠ 产物被接受** | 候选产物需有写权限成员显式确认 |
| **通知已读 ≠ 任务已知晓** | 签收状态独立于通知状态 |
| **在线状态 ≠ 可打扰** | 只表达 host 存活，不推断阅读或输入 |
| **服务端加密 ≠ 端到端加密** | P0–P3 relay 可读明文 |
| **应用层删除 ≠ 约束基础设施管理员** | 自建部署的运维者可直接操作底层存储 |

> 这八条边界在下游文档中的具体落点：
> - 撤回 ≠ 抹除 → [消息编辑与撤回](./02-collaboration-requirements.md#141-消息编辑与撤回)
> - 撤销共享 ≠ 删除 → [选择性共享](./02-collaboration-requirements.md#192-选择性共享)
> - 注销 ≠ 抹除他人副本 → [账号注销](../03-details/04-security-compliance.md#382-账号注销)
> - 执行成功 ≠ 产物被接受 → [候选产物与接受流程](./02-collaboration-requirements.md#202-候选产物与接受流程)
> - 通知已读 ≠ 任务已知晓 → [工作项与通知](./02-collaboration-requirements.md#17-工作项与通知)
> - 在线状态 ≠ 可打扰 → [在线状态](../03-details/01-identity-and-permission.md#91-在线状态)
> - 服务端加密 ≠ 端到端加密 → [加密与密钥](../03-details/04-security-compliance.md#35-加密与密钥)
> - 应用层删除 ≠ 约束基础设施管理员 → [组织删除与数据导入](../03-details/04-security-compliance.md#383-组织删除与数据导入)
