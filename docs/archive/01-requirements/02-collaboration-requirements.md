## 13. 联系人与群聊

联系人请求使用稳定请求 ID，状态为 `pending`、`accepted`、`rejected` 或 `expired`。

拉黑不是联系人状态，而是有向记录 `Block(actorAccountId, subjectAccountId)`；因此双方可以分别拉黑或解除拉黑。

**只有双方联系人关系已接受、且不存在任一方向拉黑记录时，relay 才接收私聊消息。**

联系人请求默认 30 天后转为 `expired`；发送者可重发，但对同一目标的重发受速率限制，且被拉黑时不提示差异。

删除联系人是独立于拉黑的操作：它把关系状态置为 `removed`，双方不再满足私聊接收条件，但不创建 `Block` 记录，因此对方可以再次发起联系人请求。删除联系人不删除已投递的历史消息，也不撤销已授权的附件；本地历史是否保留由用户自行选择。

### 13.1 群与成员版本

relay 拥有每个群不可变的 `GroupId`、归属范围、当前群名、成员集合与单调递增的 `membershipRevision`。

私聊和私有群以已接受联系人为成员来源；项目群以有效项目成员为成员来源，不要求成员两两互为联系人。

项目群创建者必须具备项目群管理权限，群成员的项目权限被撤销或成员被移除时，relay 在同一事务中移除其群成员资格并产生系统事件和通知。

初始版本要求被邀请者接受或拒绝群邀请，接受后才成为有效成员。

群邀请状态为 `pending`、`accepted`、`rejected`、`expired` 或 `withdrawn`，默认 14 天后过期。邀请者可主动撤回未接受的邀请；成员在邀请待处理期间被移出项目或组织时，邀请随同一事务失效。重发邀请创建新的邀请记录并沿用同一去重键，不产生重复收件箱条目。

初始版本中只有群主或项目群管理员可以邀请成员、移除成员、改群名和转让群主。

每次群操作都在同一 relay 事务中追加不可变群事件，并递增该群的 `membershipRevision`。

客户端同步 `{ GroupId: membershipRevision }` 映射，不能使用单个全局花名册版本。

联系人详情和群成员列表显示 relay 聚合后的在线状态与最近可用状态；该显示只用于选择联系对象和理解投递提示，不能替代已读回执。

### 13.2 群历史授权

新成员默认只获得群定义和邀请之后的群事件，但 P1 必须提供 `GroupHistoryGrant`，避免项目协作出现历史真空。

群主或项目群管理员在邀请流程中可选择“不共享历史”“共享最近 N 天”“共享从指定消息游标开始的历史”或“共享已标记为项目背景的历史”。授权范围还独立选择消息、附件、资源引用、工作项和仓库更新。

relay 在**一个事务**中冻结历史上限游标、创建接收人的历史读取授权、为允许的附件/资源创建受限读取授权，并写入群事件、审计和通知。**新成员只读取该不可变范围，不能因后来获得群成员资格而自动扩大到更早历史。**

历史授权带有效期，默认与组织 `RetentionPolicy` 中的消息附件授权一致（自建 30 天、团队版 90 天、企业版按策略），到期后不再可读取新内容。授权可由群主或项目群管理员续期，续期是显式命令并产生审计与通知；续期不扩大原有范围上限游标。绑定项目背景的长期授权可配置为随项目状态存续，项目归档时一并停止。

管理员可撤销未下载或未打开的历史授权；**已下载内容仍受设备本地副本限制，界面必须提示不能远程抹除**。端到端加密群的历史授权还需要相应 epoch 的密钥包；无法安全提供密钥包时，界面只允许共享项目资源和摘要，**不能虚假承诺可回溯消息正文**。

### 13.3 仓库绑定

项目群可以选择性绑定一个或多个仓库。绑定记录 `RepositoryBinding` 属于项目和群，包含仓库提供方、规范 URL、默认分支、显示名、访问模式、绑定者、版本和状态。

访问模式为 `link_only`、`read_sync` 或 `write_automation`。`link_only` 只在群资料页显示可点击仓库链接，不保存仓库 token；`read_sync` 允许 relay 验证提交和接收只读 webhook；`write_automation` 只在企业策略和独立审批通过后允许 Bot 或工作流创建分支、提交或合并请求。

绑定仓库需要项目群管理员权限。relay 对规范 URL 去重，校验仓库是否属于允许的提供方和组织范围，并将绑定事件、群系统消息和项目通知写入同一事务。

成员点击仓库链接时直接跳转到仓库提供方；**dsh-chat 不把成员个人的 Git 凭证代理给其他成员**。

仓库绑定状态为 `pending_verification`、`active`、`degraded`、`revoked` 或 `removed`。验证失败、webhook 签名不符或远端不可访问时进入 `degraded` 并通知群管理员，但不影响普通聊天和本地开发。

## 14. 消息模型

本地创建的每条消息都带有 UUIDv7 `MessageId`、不可变发送者账号、目标、类型、创建时间和客户端幂等键。

relay 将 `(senderAccountId, MessageId)` 作为幂等键，重试时返回首次接收结果。

relay 为私聊收件人队列项分配独立且单调递增的 `DeliverySeq`；群消息写入按 `GroupId + membershipRevision` 分区的 `GroupLog`，并获得单调递增的 `GroupMessageSeq`。

**relay 不以发送方时钟排列会话**；客户端以 relay 接收时间和稳定的并列排序键展示消息。

P0 支持的消息类型：

```text
text { body }
```

P1 支持的消息类型：

```text
image { attachmentId, caption? }
file  { attachmentId, filename, mime, size, caption? }
quote { targetMessageId, senderLabel, excerpt, targetType }
system { action, renderedText }
```

引用是附在新消息上的非递归快照。

接收方即使没有原消息也能渲染引用；只有原消息在本地时，点击引用才可以跳转到原消息。

> **所有展示文本都通过安全的 DOM 文本 API 渲染，任何消息字段都不得作为 HTML 插入。**

### 14.1 消息编辑与撤回

**消息正文不是可原地覆盖的字段。** 每个 `MessageId` 具有单调递增的 `MessageRevision`，初始正文为 revision 1；编辑追加不可变 `message_edited` 事件，撤回追加 `message_revoked` tombstone 事件。

编辑事件包含 `MessageId`、目标 revision、编辑者、编辑时间、策略版本和新内容摘要；只有原发送者在组织配置的编辑窗口内，且消息未被撤回、未触发保留冻结时可以编辑。接收方和 host 只接受比本地 revision 更高的事件，因此重复投递或乱序同步不会把新正文覆盖为旧正文。

撤回由原发送者或具备合规权限的管理员发起。私聊撤回写入每位已投递收件人的控制事件流；群撤回以新的 `GroupLog` tombstone 事件追加。在线和离线设备在下次同步时都收到该事件，本地把正文替换为撤回占位并保留最小审计元数据。

> **撤回不承诺擦除已被用户截图、导出、复制、端到端设备缓存或通过历史授权下载的内容。** 界面和审计记录**必须**明确“已从受控视图撤回”的边界。

引用和历史授权引用的是特定 `MessageRevision`。原消息编辑或撤回后，已发送引用仍展示发送时快照，并标记原消息当前已编辑或已撤回，**避免静默篡改历史上下文**。

## 15. 消息交互功能范围

以下功能被显式定级，避免逐项遗漏或在实现期临时加入而绕过权限与同步语义。任何被标为延后的功能，其入口在此前显示为未安装或返回 `NOT_IMPLEMENTED`。

| 功能 | 定级 | 说明 |
|---|---|---|
| 表情回应 | P1 最小模型 | 见 15.1 |
| 富文本与代码块 | P1 | 受限 Markdown 子集：粗体、斜体、行内代码、围栏代码块、链接、有序/无序列表；服务端按 schema 校验并存储结构化节点，客户端安全 DOM 渲染，不接受原始 HTML |
| 消息转发 | P2 | 见 15.2 |
| 消息线程 | P2 | 见 15.3 |
| 群公告与置顶 | P2 | 群级单条置顶与公告，属群事件，权限同改群名 |
| 群资料（头像、描述） | P1 | 头像走 `BlobObject` 与资源扫描链路，不单开上传通道 |
| 只读群 | P2 | 以群策略表达，不新增群类型 |
| 语音消息 | 延后 | 若启用，作为文件子类型处理，遵循 P2 视频的同类限制；不实现独立流媒体协议 |
| 消息定时发送、免打扰时段 | 延后 | 与通知偏好合并设计，不单独建模 |
| 已读回执（逐人可见） | 不做 | 与在线状态边界一致；账户级已读水位只用于未读计数，不向他人暴露 |
| 输入中提示 | 不做 | 属于键盘活动推断，违反在线状态边界声明 |

### 15.1 表情回应

回应绑定 `MessageId` 与具体 `MessageRevision`，记录 `(MessageId, revision, accountId, emoji)` 四元组并以其为幂等键，同一账号对同一表情重复提交为幂等。回应是独立于消息正文的轻量事件，不产生新的 `GroupMessageSeq`，通过账户状态流跨设备同步。可回应者限于该消息的有效读取者；消息被撤回后回应一并隐藏。表情集合由组织策略限定为固定白名单，不接受任意字符串或自定义图片，避免成为旁路内容通道。回应默认不产生通知。

### 15.2 转发、共享与引用的区别

三者语义不同，必须在界面上可区分：

| 操作 | 产生什么 | 权限判定 | 接收方看到 |
|---|---|---|---|
| 引用 | 附在新消息上的非递归快照 | 发送者当前对目标会话的发言权 | 发送时的正文摘录，标记原消息已编辑/已撤回 |
| 转发 | 新消息 + 不可变摘录快照 + 附件的新 `MessageContentGrant` | 逐条复检原消息读取权与附件授权 | 独立消息，标注来源类型与转发者，不含原会话上下文 |
| 共享 | `ShareableItem` 与资源 ACL 授权 | 完整共享闭环与确认 | 受控对象，可撤销、可设有效期 |

**转发不是复制物理字节**：附件复用同一 `BlobObject`，只创建接收人范围的新授权。**转发跨组织一律禁止。** 原消息所属目录禁止快照时，转发返回 `RESOURCE_SNAPSHOT_FORBIDDEN`。转发链不递归展开，只标注直接来源。

### 15.3 线程

线程是挂在某条根消息上的子序列，拥有 `ThreadId`、根 `MessageId` 与独立单调的 `ThreadMessageSeq`，但仍存储在所属群的 `GroupLog` 分区内，**不新建权限域**。**线程权限完全继承群与历史授权，不能通过线程扩大或缩小可见范围。**线程回复默认只通知线程参与者与被 @ 的成员，不打扰全群；根消息被撤回时线程转为只读并保留已发生的回复。历史授权按根消息游标整体授予或不授予线程，不做部分裁剪。

## 16. 附件与内容授权

附件和组织资源共用内容寻址的 `BlobObject` 与两阶段上传协议；消息附件、资源版本和历史授权只创建不同的元数据与访问授权，**不复制物理字节**。

1. host 创建本地附件记录，并在任何 relay 请求前保存原始字节。
2. host 请求 relay 创建上传预约；预约绑定 `MessageId`、预期目标、MIME 类型、字节长度、摘要和过期时间。
3. host 使用该预约上传字节。
4. host 发送引用该预约附件的消息。
5. 只有预约、摘要、发送者和目标全部匹配时，relay 才接收消息；同一事务把 `BlobObject` 绑定到已接收消息，并创建接收人范围的 `MessageContentGrant`。

把组织资源发送到群时，用户必须选择“发送实时资源引用”或“发送版本快照”。实时引用仅在所有目标成员已有该资源 ACL 时可用；版本快照创建一个绑定资源版本、消息、收件人范围和保留期的 `MessageContentGrant`，使接收人即使不具备目录 ACL 也可在授权期内打开该特定版本。

目录策略可以禁止版本快照，例如受限人事、财务或密钥目录。此时 relay 在发送前返回 `RESOURCE_SNAPSHOT_FORBIDDEN`，而不是发送一个接收人无法打开的死链接。

> **relay 根据已接收消息的发送者、收件人和 `MessageContentGrant` 授权下载附件，而不能只依据当前群成员关系或共享目录 ACL。**

该规则允许**退群成员在保留期内重新下载自己已获授权的媒体**，也**阻止后来入群的人读取旧附件**。

relay 必须将 `BlobObject` 保留至所有有效的消息/资源引用和 `MessageContentGrant` 到期后，再额外保留一个可配置的恢复窗口；同一 blob 被资源库引用时不能因某条消息 ACK 而删除。

附件下载失败时，消息仍然持久化，状态为 `attachmentState = pending`；host 反复重试至保留期结束，并显示“附件不可用”的终态，**而不能假装图片已经送达**。

P1 接受 PNG、JPEG、WebP、GIF 和通用文件，应用 MIME 白名单、适用时的魔数验证、可配置的大小上限、摘要验证、文件名净化和按账号/群划分的配额。

P2 中视频是文件的一个子类型，不是独立流媒体协议；启用前必须另行定义更严格的大小、时长、转码、预览、带宽和保留期限制。

浏览器以二进制 multipart 或流式请求体把选定文件交给 host；不得把数 MB 的数据扩展成 JSON base64。

host 对文本、图片、文件、说明、引用、表情回应和未来命令统一执行输入策略：最大长度、允许类型、速率限制、目标授权、幂等键和审计记录。

## 17. 工作项与通知

**工作项把“需要谁继续做什么”从聊天消息中分离出来。**

工作项属于一个项目，包含标题、描述、优先级、负责人、协作者、关联群、关联资源、截止时间和当前版本。

工作项状态为 `draft`、`open`、`assigned`、`in_progress`、`blocked`、`in_review`、`done`、`cancelled` 或 `archived`。

工作项分派另有**独立的签收状态** `offered`、`acknowledged`、`declined`、`expired` 或 `reassigned`。**它不复用聊天消息或通知的 `read` 状态。**

负责人通过明确“接受任务”“拒绝并说明原因”或“请求调整”命令改变签收状态；项目经理可以设置签收期限和逾期提醒。通知已送达或已阅读只表示收件箱状态，不能代表任务已知晓、同意或开始执行。

只有项目经理、项目管理员或被授予分派权限的成员可以变更负责人、优先级和终态；开发者可以认领已开放的工作项、报告阻塞、提交产物和请求评审。

状态变更必须使用命令而不是直接修改字段，并记录操作者、理由、前一版本、后一版本和关联产物。

工作项之间可以建立依赖关系 `blocks` 与 `depends_on`，以及父子分解关系。依赖是同项目内的显式引用，创建时校验不产生环；跨项目依赖需要双方项目的分派权限并各自留审计。父工作项不自动因子项完成而完成，但在存在未完成子项时进入终态需要显式确认理由，避免静默丢失未完成工作。

截止时间是项目本地时区下的时间点，存储为 UTC 并显示时区标识。逾期不自动改变工作项状态，只产生逾期提醒并在分析中标记；系统不因逾期自动重新分派或降低优先级，这类判断留给项目经理。

### 17.1 通知与收件箱

通知是持久化收件箱记录，不是 SSE 推送本身。

每个应通知的领域事件先在数据库事务中写入 `Notification`，再由 outbox 任务向在线 host 推送事件。

通知含接收人、事件类型、资源引用、来源操作者、最小可展示摘要、优先级、创建时间、去重键和状态。

通知状态为 `queued`、`delivered`、`seen`、`read`、`dismissed`、`expired` 或 `failed`。

浏览器 SSE 断开、桌面通知权限被拒绝或设备离线都不会让通知丢失；host 重连后从收件箱游标补拉。

通知发送失败仅影响即时提醒，不影响消息、工作项或资源的已提交状态。

默认通知事件包括联系人请求、群邀请、在线状态订阅变化、@ 提及、工作项分派或变更、评审请求、共享资源、协作会话邀请、仓库绑定或提交更新、Bot 响应、上传失败和权限变更。

去重键与聚合是两件事。去重键防止同一领域事件重复投递产生多条记录；聚合把多个不同事件折叠为一条可展开的收件箱条目。

聚合按 `(接收人, 来源对象, 事件类型)` 在可配置的聚合窗口（默认 5 分钟）内进行：同群的多次 @ 提及折叠为一条“N 条新提及”，保留最早与最新事件引用和计数，不生成 N 条独立记录；同一工作项的连续状态变更折叠为最新状态并保留变更次数。聚合条目的已读语义作用于整条，展开后逐条跳转。

安全类通知、工作项签收请求、权限变更和风险处置不参与聚合，始终逐条呈现。聚合只影响收件箱呈现与推送节流，不影响审计事件的逐条完整性。

用户可按组织、项目、群、事件类型和优先级设置静默、仅收件箱、页面角标或桌面通知；项目管理员不能绕过成员的个人静默设置，除非组织明确配置紧急事件策略。

已验证邮箱只接收设备注册、异地登录、密码/认证方式变更、设备撤销和组织安全管制等事务性安全邮件。此类邮件不能被普通项目静默规则关闭，但用户可以在安全设置中更换邮箱或启用更强验证方式。

## 18. 评审与评论

评审是工作项从 `in_review` 进入 `done` 的显式关口，不是聊天消息里的口头确认。

评审请求包含 `ReviewId`、目标工作项、请求者、指定评审人、关联产物版本或 `CodeChangeRecord`、请求说明和截止时间。评审状态为 `requested`、`in_progress`、`approved`、`changes_requested`、`declined`、`expired` 或 `superseded`。

评审人必须是有该项目读取权限的成员，且默认不能是提交者本人；组织策略可要求最少评审人数或指定角色，企业版可要求双人评审。指定评审人产生签收类通知，其送达或已读不代表评审已开始。

`approved` 只对评审时锁定的产物版本生效。关联产物或提交在评审后发生变化时，评审自动转为 `superseded` 并要求重新评审，不允许“批准一个版本、合入另一个版本”。

只有获得组织或项目策略要求的评审结论后，工作项才能由有权成员转入 `done`；策略未要求评审的项目可直接完成，但该差异必须记录在项目配置并写入分析口径，避免跨项目排行时把“无需评审”误算成高效率。

评论属于工作项、资源版本、评审或协作会话，不属于群消息，因此不进入 `GroupLog`，也不参与消息撤回语义。评论包含作者、目标对象与版本、正文、创建时间和 `CommentRevision`；编辑追加修订，删除写入 tombstone 并保留作者与时间。

拥有 `comment` 访问级别的成员可以阅读目标对象并发表评论，但不能修改对象本身、不能改变工作项状态、不能发起或批准评审，也不能再共享。评论中的 @ 提及只能指向对该对象已有读取权限的成员；提及无权限成员时返回 `FORBIDDEN`，不静默丢弃提及也不因此授予访问权。

评论正文与消息正文遵循同一输入策略与安全渲染规则，并同样作为不可信内容处理。

## 19. 共享存储与选择性共享

### 19.1 组织共享存储

组织共享存储不是成员本地媒体目录的集合，而是 relay 管理的版本化资源库。

资源库按组织、工作区和项目建立根目录；每个目录和资源都有独立 ACL、配额、保留策略和版本历史。

资源类型包括文件、图片、视频、文档、代码补丁、压缩包、DSH 生成产物和外部引用。

上传流程使用与消息附件相同的预约、摘要校验和分块上传机制，但资源在上传完成后先处于 `staged` 状态。

上传者提交元数据和目标目录后，relay 创建 `ResourceVersion`；内容校验、病毒扫描或组织要求的人工审批通过后，版本才进入 `available`。

资源版本状态为 `staged`、`scanning`、`approval_pending`、`available`、`rejected`、`quarantined`、`deleted` 或 `expired`。

下载请求总是指向具体 `ResourceVersion`，relay 在每次下载时检查调用者成员状态、目录 ACL、资源 ACL、版本状态和有效期。

同名覆盖不会覆盖旧版本，而是创建新版本；当前版本切换需要目录编辑权限，并产生通知和审计事件。

删除使用软删除和保留窗口。保留窗口结束前，组织管理员可以恢复；物理清理后返回 `RESOURCE_GONE`。

资源库、消息附件、工作项、共享对象、协作会话和 Bot 通过 `ResourceVersion` 或 `BlobObject` 引用同一物理内容。消息侧只保存引用与 `MessageContentGrant`，不能把文件内容复制进聊天数据库，也不能绕过目录禁止快照的策略。

### 19.2 选择性共享

可共享对象统一称为 `ShareableItem`，包括消息选段、附件、图片、文件、DSH 生成产物、工作项、项目说明、协作会话和版本快照。

共享者必须在发送前明确选择对象、目标组织/工作区/项目/群/成员、访问级别和有效期。

访问级别为 `view`、`comment`、`edit` 或 `continue`；被共享者不能再共享，除非共享者或资源策略显式授予 `reshare`。

对聊天消息的共享默认创建不可变摘录快照，而不是授权接收方浏览整个原始私聊。

对文件的共享创建版本化资源引用；接收方只能下载被授予的版本，后续版本必须再次共享或继承明确的目录权限。

对 AI 生成产物的共享必须显示产物来源、模型/工具标记、生成时间、人工编辑状态和已选上下文范围；它不能伪装成某个成员手写的结论。

`ShareableItem` 状态为 `draft`、`pending_confirmation`、`published`、`revoked`、`expired` 或 `deleted`。

共享操作遵循以下闭环：

1. 浏览器创建本地草稿，host 验证资源权限和目标成员状态。
2. 用户确认摘要、目标和访问级别后，host 向 relay 发送带幂等键的发布命令。
3. relay 在一个事务中写入共享记录、资源 ACL、审计事件和接收人通知。
4. relay 返回 `published` 后，发送方界面才显示“已共享”；超时则查询同一幂等键，不能盲目重复授权。
5. 接收人打开通知时，relay 在读取资源前再次检查组织成员、资源 ACL、有效期和资源状态。

权限不足返回 `FORBIDDEN`，目标已离开组织返回 `RECIPIENT_INACTIVE`，资源版本冲突返回 `VERSION_CONFLICT`，过期或撤销资源返回 `SHARE_UNAVAILABLE`。

撤销共享只能阻止后续读取，不能删除已经下载的本地副本或已经被复制到其他已授权产物中的内容；界面必须明确这个限制。

## 20. 协作会话与开发交接

个人 DSH 会话默认是私有的，不能因为加入组织、群或项目而被其他人继续、搜索或提供给 Bot。

用户需要交接开发工作时，从个人会话显式选择一段对话、相关文件、终端输出和已生成产物，创建一个 `CollaborationSession`。

创建者必须确认要公开的上下文范围，并为每个输入生成不可变快照；没有被选中的私人上下文不进入协作会话。

`CollaborationSession` 属于一个项目，带有成员 ACL、目标、当前工作分支或资源版本、关联工作项和独立的 DSH 会话 ID。

协作会话状态为 `draft`、`pending_review`、`active`、`paused`、`completed`、`revoked` 或 `archived`。

拥有 `continue` 权限的成员可以创建一次协作执行尝试，而不是接管创建者的私人会话。

执行尝试状态为 `queued`、`running`、`waiting_for_input`、`succeeded`、`failed`、`cancelled` 或 `superseded`。

### 20.1 沙箱执行约束

执行尝试只能由 `ExecutionProvider` 在独立沙箱中运行，不能在 relay 主进程、成员 host 主进程或 Bot host 主进程内直接执行命令。P2 开始前必须先实现并验收该 provider。

每次尝试创建一个临时工作区，只读挂载经过授权的仓库提交或资源版本；可写输出只能写入临时目录和明确的结果目录。尝试默认没有网络、没有宿主文件系统访问、没有环境变量继承、没有 Docker socket、没有组织秘密和没有用户私人 DSH 会话。

网络、仓库写入、特定命令、包缓存和秘密访问采用逐项能力授权。秘密由短期秘密 broker 按尝试、目标仓库、分支和时限签发，不能写入日志、产物、环境转储或后续尝试。

每个沙箱设定 CPU、内存、磁盘、进程数、网络字节、执行时长、日志字节和并发数配额；超过任何配额时运行时终止尝试，状态为 `failed` 且错误码为 `SANDBOX_QUOTA_EXCEEDED`，保留安全检查点但不自动发布产物。

拉取仓库、构建、测试和 AI 工具调用都在尝试预算内计费。用户或管理员取消、设备受控、项目权限收回、仓库绑定撤销或租约到期时，provider 终止进程树、回收临时目录和短期秘密。

尝试创建提交、分支或合并请求前必须显示变更摘要并获得拥有写仓库权限的成员确认；自动化 Bot 只能使用独立服务账号和受限分支，不能把写权限借给个人设备。

同一工作项允许多人讨论，但同一可写资源版本只允许一个持有租约的执行尝试修改；其他尝试进入只读、等待或创建独立分支，提交时使用版本比较避免覆盖。

### 20.2 候选产物与接受流程

成功的交接会把结果作为新的产物版本或合并请求写入项目，并通知创建者、负责人和订阅者。

执行成功不等于产物被接受。尝试产出先进入 `pending_acceptance` 的候选产物，携带来源尝试 ID、输入快照引用、变更摘要、资源消耗和 AI 使用引用；**候选产物默认只对协作会话成员可见，不自动成为资源库当前版本**。

接受候选产物需要拥有目标资源写权限的成员**显式确认**，确认时展示与当前版本的差异摘要和版本比较结果。版本在尝试期间被他人推进时返回 `VERSION_CONFLICT`，**接受者只能基于最新版本重新比较或另建分支，不能覆盖**。

拒绝候选产物需要记录理由，产物转为 `rejected` 并保留可追溯记录；候选产物按 Bot/协作执行日志的保留期清理。

失败、取消或租约过期会保留执行日志、最后安全检查点和失败原因；不会自动把半成品写入共享资源，也不会悄悄归属给原创建者。

协作会话的执行日志、候选产物和输入快照与其来源的个人会话解耦：原创建者撤销协作会话后，已接受的产物版本仍归属项目并保留归因，未接受的候选产物停止可见并按保留期清理。撤销不追溯删除接手者已合法获得的产物，界面必须说明这一边界。

## 21. 搜索与索引

搜索是被权限约束的查询能力，**不是对全部历史的自由文本扫描**。任何搜索结果都必须能被独立的授权检查复算；**索引命中不构成读取授权**。

可搜索范围按对象类型分别定义，不共用一个全局索引：

| 对象 | 索引源 | 可搜字段 | 范围约束 |
|---|---|---|---|
| 群消息 | `GroupLog` 已提交事件 | 正文、发送者、时间、附件文件名 | 只索引调用者拥有历史授权的区间 |
| 私聊消息 | 本地已持久化投递记录 | 正文、时间、附件文件名 | 仅 host 本地，不进 relay 索引 |
| 资源版本 | `ResourceVersion` 元数据 | 文件名、标题、标签、目录路径 | 默认不索引文件正文 |
| 工作项 | 工作项字段 | 标题、描述、负责人、状态 | 按项目 ACL |
| 代码更新 | 已 `verified` 的 `CodeChangeRecord` | commit 摘要、分支、关联工作项 | 不索引代码正文与私有 diff |
| 插件目录 | 已 `published` 的发布记录 | 包名、用途、发布者 | 按组织目录可见性 |

索引管线以领域事件为唯一输入，与 outbox 共用投递语义：`message_accepted`、`message_edited`、`message_revoked`、`resource_available`、`resource_quarantined`、`code_update_verified` 和工作项状态事件驱动增量更新。索引任务是可重放的异步任务，具有与其他异步任务相同的 `queued` 至 `dead_letter` 状态；索引失败只影响可发现性，不影响消息、资源或工作项的已提交状态。

索引条目状态为 `pending`、`indexed`、`stale`、`suppressed` 或 `purged`。`message_revoked`、`resource_quarantined`、历史授权撤销、成员移除和保留期到期都必须产生 `suppressed` 或 `purged` 转换；撤回的消息正文不得在索引中残留。索引删除与 `RetentionPolicy` 同批次执行，不单独设定更长的保留期。

查询执行顺序固定：解析 `OrganizationId` 与成员状态，计算调用者可见的索引分区，执行受限查询，然后对每条候选结果**逐条**复检资源 ACL、历史授权区间、对象状态和有效期，最后才返回。**复检失败的条目静默丢弃，不返回占位符，也不在总数中计入，避免通过结果计数推断不可见内容的存在**。

搜索请求受独立的速率、结果条数、分页深度和查询复杂度上限约束；不支持可导致全库扫描的前缀通配、正则或空查询。查询词、结果 ID 和调用者写入审计，但查询词不写入普通日志。

索引按 `OrganizationId + policyRevision` 分区。切换组织时 host 关闭前一组织的索引句柄；**跨组织搜索在任何层级都不可用，包括管理员与分析角色**。

端到端加密模式下服务端搜索的降级遵循 `OrganizationEncryptionPolicy` 功能矩阵：

| 模式 | 服务端索引 | 客户端本地索引 | 说明 |
|---|---|---|---|
| `server_managed` | 全部可搜对象 | 可选加速 | relay 按权限读取正文构建索引 |
| `e2ee_without_bot` | 仅元数据（文件名、标题、工作项、提交摘要） | 消息正文仅在成员设备本地索引 | relay 强制禁用正文索引 |
| `e2ee_with_bot_member` | 同上 | 同上 | Bot 设备的解密能力不用于构建服务端索引 |

设备侧本地索引只覆盖该设备已同步并解密的区间，因此不同设备的搜索结果可能不同；**界面必须显示已索引区间和“更早历史需在其他设备或补拉后可搜”，不得让用户误以为结果是全量的**。本地索引与解密材料同等保护，设备进入 `restricted` 时随敏感缓存一并清除。

P0 只提供 host 本地的私聊与联系人查找，relay 不提供搜索 API，入口显示为未安装。P1 加入群消息与资源元数据的服务端索引。P3 加入工作项、代码更新与插件目录搜索。P4 按上表执行 E2EE 降级，并在切换加密模式前把索引能力变化写入管理员确认的降级清单。

## 22. 仓库与 AI 辅助开发记录

`CodeChangeRecord` 将一个已验证的 Git 提交与项目、仓库、作者、工作项、协作会话和 AI 辅助来源关联起来。

记录包含 `RepositoryBindingId`、完整 commit hash、父 hash、分支或合并请求、外部作者标识、映射后的组织账号、提交时间、变更统计、关联工作项、关联协作会话、AI 使用引用和验证来源。

AI 使用引用只表明该提交在明确的 DSH/公共插件/Bot 调用后产生，或用户在提交前主动关联了这些调用；**它不能证明每一行代码都由 AI 生成，也不能替代代码评审**。

host 可以在用户提交代码后创建 `reported` 记录，但只有仓库提供方 webhook、受限 API 查询或可信镜像验证了 hash、仓库和作者映射后，记录才变为 `verified`。

记录状态为 `reported`、`verifying`、`verified`、`rejected`、`orphaned` 或 `superseded`。

`rejected` 表示 hash 不存在、仓库不匹配、webhook 签名无效或作者映射冲突；`orphaned` 表示提交存在但无法安全映射到组织成员或项目；两者都不进入成员贡献、周报或排行榜。

一次提交可关联多个 AI 调用和工作项，一个 AI 调用也可以关联多个提交。**关联必须由用户或项目策略明确发起，不能通过提交信息中猜测关键词自动建立。**

relay 以 `(RepositoryBindingId, commitHash)` 去重。远端强制推送、分支删除或合并重写不会删除历史记录，而是新增更新事件并把受影响记录标记为 `superseded` 或保留其最后验证状态。

项目群展示最近的已验证提交、关联工作项、作者、评审/合并状态和 AI 辅助标记；点击 hash 跳转到仓库提供方。默认不在群内展示代码正文、私有 diff 或未验证的提交摘要。

Bot 或工作流提交代码时**必须**使用独立服务账号和独立分支，记录 `authorKind = bot`；**系统不得把该 hash 计入任何人类成员的开发统计或排行**。

## 23. 群内公共 Bot

群 Bot 是**独立配置的 DSH 智能体身份，不是任一成员私人 DSH 会话的共享副本**。

创建或启用群 Bot 前，relay 必须检查 `OrganizationEncryptionPolicy`。`e2ee_without_bot` 模式下 Bot 入口、调用 API、自动触发器和相关插件目录项全部不可用；`e2ee_with_bot_member` 模式下只允许已被成员确认的 Bot 设备参与相应群 epoch。

### 23.1 权限静态绑定

> **Bot 的权限静态绑定在其 `BotServiceAccount`、项目 ACL、能力清单和预算上，不随调用成员的角色动态提升。** 调用者只能证明“有权请求这个 Bot”，**不能把自己的文件、协作会话、秘密或写仓库权限借给 Bot**。

Bot 读取资源时使用 `botCapability ∩ botResourceAcl ∩ invocationPolicy` 的交集。**人类共享给另一名人类的 `CollaborationSession` 默认不授予任何 Bot**；需要 Bot 读取时，资源所有者**必须**单独创建带范围、时限和只读权限的 `BotAccessGrant`。

若组织确实需要委托，使用**不可转授权、最小范围、短时效**的 `DelegationGrant`，并同时满足调用者和 Bot 的静态权限；**它不能包含私人会话、设备私钥、长期仓库 token 或组织管理能力**。

### 23.2 调用与上下文冻结

群主通过明确群命令添加 Bot，并选择其模型或 preset、允许工具、最大上下文、数据保留期、速率限制和可调用成员。

relay 只有在验证成员身份和 Bot 策略后，才会把 Bot 调用路由给 Bot host。

Bot host 为每个 `(GroupId, BotId)` 创建或恢复一个隔离的 DSH 会话。

该会话的上下文只包含 Bot 策略明确允许的群消息、Bot 响应和配置的系统指令；**它绝不读取成员个人 DSH 会话或私聊内容**。

Bot 响应是带有 `authorKind = bot` 和 Bot 身份标识的普通群消息，并且永远按不可信纯文本或受限附件渲染。

> **只有用户在客户端显式提交的交互意图才会进入命令解析器。群消息、Bot 输出、AI 输出、仓库 webhook、插件输出和引用文本绝不被二次解析为斜杠命令、工具调用、确认动作或权限请求。**

Bot 只可以响应显式 @、由用户界面生成的命令调用或已启用的触发策略发言；每条自动消息都带调用引用，并受速率和工具权限约束。

移除 Bot 后停止后续处理，并按照群保留策略删除或归档该群 Bot 会话。

公共 Bot 的共享上下文采用“项目记忆”而不是无限群记录：策略定义可读取的群、项目资源目录、工作项状态、最大消息数、最大字符数和保留时间。

每次调用先**冻结本次允许的上下文清单**，再向 Bot host 发送；**调用期间的新消息和后续权限变化不自动混入同一请求**。

Bot 可以把可复用的总结、计划、代码建议或文件产物发布到项目资源库，但发布前必须经过项目策略规定的人工确认，或者被标记为 `bot_generated` 且限制为草稿可见。

Bot 调用状态为 `requested`、`authorized`、`queued`、`running`、`awaiting_confirmation`、`published`、`rejected`、`failed`、`cancelled` 或 `expired`。

Bot host 超时、模型失败、工具拒绝和策略违反都进入 `failed`，保留不含秘密的失败摘要并通知调用者；这些失败不会改变工作项状态、覆盖项目资源或以成员名义发言。

## 24. 公共插件与工具目录

组织公共插件是管理员审核后供成员一键启用的 DSH 插件、工具、工作流或 Bot 模板。

公共插件属于组织或工作区，不属于某位成员的个人 profile；成员点击启用后，插件安装到本人的 DSH profile，但其可访问的数据和服务仍受组织策略与资源 ACL 限制。

插件发布记录至少包含包名、精确版本、发布者、来源、签名或摘要、用途、支持平台、配置 schema、所需权限、数据流说明、变更记录和回滚版本。

插件权限以能力声明表达，包括读取指定项目资源、写入指定项目资源、发送群消息、调用模型、使用外部网络、读取组织秘密、运行工作流和代表 Bot 发言。

组织管理员**不能以“已审核”为理由让插件绕过成员、项目或资源权限**；每次敏感调用仍在运行时校验调用者和目标资源。

插件发布状态为 `draft`、`submitted`、`reviewing`、`approved`、`published`、`deprecated`、`revoked` 或 `rejected`。

发布链路如下：

1. 发布者提交精确包版本、权限清单、测试证据和数据流说明。
2. 审核者检查来源、签名、依赖、权限、网络目标、秘密读取范围和回滚方案。
3. 审核通过后，relay 写入不可变发布版本和组织目录事件；成员收到“可用工具”通知。
4. 成员一键启用时，host 下载已批准的精确版本并再次展示所需权限；安装失败只影响该成员，不撤销已发布版本。
5. 管理员撤销版本后，relay 在同一事务中将版本设为 `revoked`、递增插件策略修订、使启用令牌和能力租约失效、写入撤销 outbox 与审计。调度器立即停止排队任务；运行中的插件/Bot/工作流收到带截止时间的取消命令，截止前未退出则由其执行 provider 强制终止进程或隔离实例，并回收网络、秘密和写入租约。任何迟到结果都因版本或能力租约已失效而被 relay 拒绝。host 收到失效事件后立即禁用版本，不能等待下一次常规同步。

插件升级**不是静默替换**。新版本必须重新审核，成员或管理员按组织策略选择立即升级、分批升级或保持旧版本至截止日期。

企业版可配置审批人、双人审批、允许来源、软件物料清单、漏洞扫描、签名策略和分阶段发布；自建组织至少要保留发布者、版本、权限和撤销记录。

## 25. 仪表盘、报告与排行

组织仪表盘服务于容量、成本、协作流转和交付质量管理，**不把聊天内容、私人会话或原始提示词当作统计数据**。

组织所有者和具备分析权限的管理员可以查看组织级 token、模型成本、活跃成员、项目流转、Bot 调用、共享存储、插件使用和已验证代码更新的聚合数据。

项目经理只能查看自己有权限的项目及其成员汇总；普通成员默认只能查看自己的数据和项目的匿名分布。

原始用量事件由 host、relay、Bot host 和经批准的插件产生，至少包含组织/项目/工作项引用、账号或服务账号、角色族、事件时间、模型、输入 token、输出 token、缓存 token、计费金额、调用耗时、执行尝试和匿名化关联 ID。

已验证的 `CodeChangeRecord` 是独立分析来源，提供提交、评审和工作项流转事实；它不上传仓库代码正文，也不把代码行数直接转换为个人得分。

**AI 辅助编码指标不直接把“模型生成代码行数”当作贡献或排行依据。**

系统可记录 AI 生成建议是否被接受、关联的代码提交/评审、工作项复杂度、返工次数、评审结果和执行耗时；**这些都是可审计的辅助信号，不是自动绩效结论**。

分析事件状态为 `collected`、`validated`、`attributed`、`aggregated`、`published`、`corrected` 或 `suppressed`。

无项目归属、缺少授权、来源不可信或不满足最小样本量的事件不能进入个人排行，只能进入经脱敏的运维汇总或被 `suppressed`。

### 25.1 token 与成本大屏

组织大屏显示可配置时间窗内的输入/输出/缓存 token、模型成本、预算消耗、按项目/模型/公共插件/Bot 的分布、超额预测和异常峰值。

默认只显示聚合趋势；查看个人明细需要组织策略明确允许，且查询会留下审计记录。

预算告警按照组织、工作区、项目、Bot 和插件分别设置阈值。告警创建持久通知，可选择阻断新的付费调用、降级到指定模型或等待管理员批准；不能中断已经提交且有安全检查点的协作执行。

### 25.2 个人工作台与个人排行

个人设置页提供“我的工作台”，展示当前组织和可切换组织、绑定设备与登录方式、在线状态可见范围、个人 token/模型成本、预算归属、工作项、最近验证提交、AI 辅助记录、通知和个人周报入口。

个人 token 数据按组织、项目、模型、插件、Bot 和时间窗拆分，显示输入/输出/缓存 token、成本、预算限额和数据来源。**成员只能查看自己的逐项用量，不能借由项目统计反推其他成员的私人调用。**

个人排行页只显示用户在有资格的比较组中的当前分位、分数构成、样本量、计算策略版本和可更正数据；**没有合格比较组时明确显示“不参与排行”，而不是显示零分或空名次**。

### 25.3 AI 协作月报与周报

系统根据经过验证的工作项、资源版本、代码提交/评审更新和用量聚合，生成个人、项目和组织级周报/月报草稿。

报告草稿明确标记为 AI 生成，列出数据时间窗、可追溯来源、缺失数据和计算口径；发布者必须确认后才能将其共享给其他成员。

成员可以选择订阅个人周报，项目经理可以按项目生成周报，组织管理员可以生成组织月报。订阅和共享对象均遵循成员权限与通知偏好。

**月报不得自动宣布人员评价、晋升建议、淘汰建议或排名结论。** 它只描述可验证的协作事实、成本趋势、风险、阻塞项和待确认事项。

### 25.4 同层级效率排行

排行只在同一比较组内计算。比较组由组织配置的 `roleFamily`、职级区间、项目类型、工作项类别和统计时间窗共同确定。

**项目经理、开发者、设计者、运维和 Bot 服务账号永不进入同一排行榜。**

比较组必须同时满足最少有效成员数和每位成员最少完成工作项数；**不满足时只显示个人趋势和匿名分布，不显示名次**。

每个完成工作项先由负责人确认复杂度和工作类型，开始后修改必须写明理由并进入审计；无法确认复杂度的工作项不进入排行。

同层级效率分只使用以下可解释、可复核的维度：

| 维度 | 默认权重 | 计算原则 |
|---|---:|---|
| 交付质量 | 45% | 已通过评审、验收后返工率和阻塞恢复情况；质量不足不能被速度抵消 |
| 周期效率 | 35% | 实际活跃执行时长相对同类工作项的期望时长；不使用日历在线时长 |
| 资源效率 | 20% | 在相同工作项复杂度和角色组内，归一化后的模型成本与 token；更少资源不代表牺牲质量 |

默认权重属于 `OrganizationAnalyticsPolicy`，**必须**由组织管理员配置并记录生效版本；**项目经理不能为某个成员临时改权重**。

排行使用分位数或标准化分数，并展示分数构成、样本量、时间窗和数据缺口；不得只展示一个不解释来源的总分。

成员可以查看自己的全部明细并提出数据更正；项目经理只能在其授权项目内查看具名排行；组织可选择完全关闭具名排行或仅公开前后分组而不公开名次。

> **排行结果只能用于协作改进和资源规划。系统不支持把它自动写入人事档案、触发惩罚、调整薪酬或变更角色。**
